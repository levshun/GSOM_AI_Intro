# Glossary: Data Collection & Cleaning

Simple definitions of terms used in the course, sorted alphabetically.

**Agent (in OpenCode)** – A special-purpose assistant defined in an `.md` file
under `.opencode/agent/`. The file has frontmatter (description, mode, model,
permissions) and a body that is the agent's instructions.

**AGENTS.md** – A Markdown file read by OpenCode that describes a project: its
structure, rules and conventions. Every assistant working in that folder sees it.

**API (Application Programming Interface)** – A standardized way for programs to
talk to each other. Agents connect to an LLM through an API.

**CATA** – A prompt recipe from the sister course: pick C (Context), A (Action),
T (Tone/format) and A (Anticipate edge cases). Compose every prompt with it.

**Clean data / cleaning** – Making a dataset usable: normalize text and numbers,
remove duplicates, parse dates, handle missing values, and flag outliers.

**Completeness** – How few missing values a dataset has. Measured per column.

**Consistency** – When the same thing is written the same way everywhere
(one spelling for each category, one date format, one currency symbol).

**CSV (Comma-Separated Values)** – A plain-text table format that pandas can
read directly.

**Duplicate** – Rows that repeat the same record, exactly or almost. Cleaning
decides which copy is kept and records how many were dropped.

**HTTP / HTML / robots.txt** – HTTP is the request/response protocol of the web;
HTML is the markup of a page; robots.txt is the text file a site publishes to say
what may or may not be accessed by bots.

**Missing value** – An empty or unknown cell (`NaN`, empty string, `"N/A"`,
`"unknown"`). Cleaning must turn all spellings into one representation (`NaN`).

**Outlier** – A value far outside the sensible range (e.g. a multi-million spend
for one customer). Cleaners usually *flag* outliers, not silently delete them.

**PII (Personally Identifiable Information)** – Personal data (name, email).
Synthetic data must avoid real PII; real PII must be protected.

**Prompt** – The text you send to an assistant: context, instructions, expected
output format, and your "checkpoint" (how the answer will be verified).

**Schema** – The blueprint of a table: which columns exist and their types,
ranges, and constraints (e.g. age 18-90, spend non-negative).

**Scraping (web)** – Automatically reading structured data out of web pages.
Ethically and legally constrained (robots.txt, terms of service) - hence we
practise on a local snapshot.

**Synthetic data** – Fake but realistic data generated by a script or an LLM,
used to avoid privacy issues and to create edge cases for testing.

**Tidy data** – Data in a clean shape: every column a variable, every row an
observation, no duplicated pieces. A common goal of cleaning.

**Token** – The unit of text an LLM reads/writes (~4 characters). Relevant here
because long prompts (big context) cost more.

**Validation** – Checking a cleaned dataset against rules (completeness,
uniqueness, types, ranges) and reporting numbers, not opinions.
